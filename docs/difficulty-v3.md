# 《折信》难度 v3（2026-10-25）：人一眼看见的，比求解器算出来的多

> **校准点**（主人，10/25 13:07–13:10）：卷一 25/25、第五章「胶」7/7、第六章「翻」6/7（只剩 6-7），一个上午打完，「我觉得还是有点简单」「没什么卡住我的地方」。三封「暗信」0/3：「暗信设计的还行 有点难度」。这是**第三次**（`difficulty-postmortem.md`：0.1(13) 的章末 20–30 s）。我们的门禁（`check.js` 解长 / 岔路 / 死局盆地）和文字采样器（`tools/play.js`，10/24 盲测 6-4 要 8–20 次调用、6-7 要 12–16 次）说"难"，人说"易"。

> **本文**：① 诊断——人一眼看见什么，为什么我们的工具看不见它；② 以暗信为靶心（唯一卡住主人的内容）的 v3 设计原则；③ 新门禁：**视觉采样器 + 一眼测试**（`tools/glance.js`，已实现、已跑完第五、六章全部 17 关）；④ 改哪些关、改几关、什么顺序，以及第七章「墨晕」怎么一开始就按 v3 做。**本文不改任何关卡。**

## 0. 一页结论

- **人一眼看见的是状态，不是动作。** 这个游戏里一切要紧的事都能在十秒内免费看见：斜起看影子滑（可逆），合上再撤销看盖印后的图，合上翻过来再撤销看第三页。看完之后每关主线 hard / final 都只剩**一道题：找到那一格——从哪一格合（或翻），哪道影子到得了它**。`check.js` 的 `wrong = 15`、`dead = 55%` 数的是一个**看不见棋盘**的人会犯的错；看见棋盘的人一个也不会犯。
- **一眼测试证实了这一点**：把人能看见的全部视图印成一张纸给一个从未见过这关的模型，一次写出路线——17 关里 **15 关至少一位读者一次写对**，主线 hard 6 关 **6/6 两位都一次写对**，两关 final 两眼之内 2/2。只有**暗一、暗三**顶住了（0/2 一眼；两眼 1/2、0/2），和主人的 0/3 一致。暗二一眼就破（2/2）。
- **暗一、暗三难在哪**：解里有一步的正确性**不在任何视图上**——站在左页石头正上方的右页格合书，你就在一叠"看起来堵死（#）"的纸里；三次盖印、每次站的位置决定你在哪一页。这是**规则后果**，不是棋盘事实。v3 的全部原则都是围绕"把难度从棋盘事实挪到规则后果"。

## 1. 诊断：为什么人觉得简单

### 1.1 一切要紧的状态都能免费看见

游戏里有撤销（U）、有连续角度，所以下面每一样都是**零成本、可逆**的"看"，不是"做"：

| 你想知道 | 怎么看（≤ 2 s） | 对应 `glance.js` 的视图 |
|---|---|---|
| 影子在哪、怎么滑 | 拇指拖页从 80° 到 30°，看左页 | VIEW 2（七个采样角并排） |
| 合上会压死我吗 | 看对面那格是不是石头 | VIEW 3 第一行 |
| 合上棋盘会变成什么 | 合上、撤销 | VIEW 3 事件 + VIEW 4（盖印后的图） |
| 合着能走到哪、在哪一叠换页 | 合上看叠（灰盒按叠画） | VIEW 3 叠合图（`top/under`，# 为堵） |
| 第三页长什么样 | 合上、翻、打开、撤销 ×3 | VIEW 5–6 |
| 盖印后新石头的影子 | 合上、打开、斜 | VIEW 4b |

`stamp()` 不看人站在哪，所以"合上之后的图"是**确定的一张**，看一次就够。于是每关主线 hard / final 真正没写在屏幕上的信息只剩 1 bit：**合着走完之后你在哪一页**（`land()` 的历史）。一个 bit，人心算得过来。

### 1.2 每关都是同一道题：找那一格

把 1.1 的视图叠起来，人的解法是倒推三步：① 终点那一叠（翻过去 / 合上时）连着哪些叠 → ② 要在左页的哪一格合（翻）→ ③ 哪道影子（哪个角度）到得了那一格。三个问题的答案全在视图上。逐关：

| 关 | 人一眼看见什么 | 剩下要"想"的 | 一眼测试 |
|---|---|---|---|
| **6-7 末页** final | VIEW 3 叠合图里 (3,5)(3,6)(4,6) 三叠是孤岛，其余叠连成一片——所以**第一合必须站在那三叠里**（右页 6,5），这是图上的连通性，不是推演。合上后 VIEW 4b：新石头 7,5 的影子在 55° 落在 (3,5)，正好接 (3,6)→(1,5)。VIEW 5 叠合图：第 1 叠从 row 5 直通 row 1 的 G | 从 (3,6) 出发影子该用哪个角（表上直接读） | A 一眼错（没看叠合孤岛），两眼对；B 一眼对 |
| **6-4 夹层** hard | VIEW 2：40°–50° 顶行 (3,1) 和第 3 行 (3,3) 同时是 ░；VIEW 5 叠合图：G 在第 3 叠 row 3，从 row 1 第 4 叠 (./.) 往下两格通。**「两块石头，一个角度」这句话把表都省了** | 无——两位读者各走了不同的影子路，都对 | 2/2 |
| **5-7 两盏灯** final | VIEW 4b 盖印后：两道影子同在第 2 列（row 1、row 4），墨印在 (3,3) 把它们接起来；G 在 (1,1)。VIEW 3：合上压人只在胶上 | 乘影要先开到 60° 再合回 50°——角度不单调，但表上两行 ░ 的位置就是答案 | A 一眼错（叠合里没换到左页），两眼对；B 一眼对 |
| **6-5 透字** hard | VIEW 3：「胶把 2,2 的石头粘走」+ VIEW 4b 影子消失 → 先别合，这是 `before`，但一眼就读出；VIEW 2：55° 影子 (3,2)、70° 滑到 (4,2) | 乘影朝打开方向：读表 | 2/2 |
| **6-6 压花** hard | 同 6-5：胶的后果在 VIEW 3 一句话里；40°→60° 的乘影在 VIEW 2 两列里 | 无 | 2/2 |
| **5-4 旧处 / 5-5 渡 / 5-6 两合** hard | 「对岸没有石头」= 先合造影子：VIEW 4b 直接印出造好的影子 | 无 | 2/2 · 2/2 · 2/2 |
| **6-3 两面** mid | 60° 的 ░ 接第 4 列；翻过去第 2 叠通顶 | 无 | 2/2 |

共同点：**每关只有一次"棋盘改变"（合或翻），而且改变前后两张图都看得见**。`before`（先别合）在第五章 5-4 教过一次之后对同一个人是常识；「页角有胶。别急。」一句话还把它说出来了。

### 1.3 为什么门禁和文字采样器说难

- **`wrong` / `dead%` 数的是看不见棋盘的错。** 6-5 `wrong = 15`、死局 55%：这 15 个岔路里绝大多数是"在别的格合上""在别处翻"——VIEW 3 / VIEW 5 一行字就排除了。人不会走进一个**写在屏幕上的**死局。
- **`len` 数走路。** 18–20 的解长里 14–16 步是走路；走路免费、路径唯一，人用两秒。
- **文字采样器是顺序读图的。** `play.js` 每次调用印一张 8 列图 + 一段叠合图；读者要在脑子里拼出"所有角度的影子"和"合上之后的图"，拼错一次就是 3–5 次调用。10/24 盲测的 8–20 次调用量的是**拼图的代价**，不是谜题的深度。换成一张把全部视图印好的纸，同一个模型一眼写对。**文字采样器量的不是人的难度，是读图接口的难度。**
- **`greedy` / `misdirect` 的天真玩家不会撤销。** 真人会。

### 1.4 暗信做对了什么（主人的 0/3 vs 主线 13/13）

| | 主线 hard / final（5-4…5-7、6-4…6-7） | 暗一 · 暗二 · 暗三 |
|---|---|---|
| 棋盘变化次数（盖印 / 翻） | **1**（6-7、5-6 为 2，但第二次不改图） | **2 / 2 / 3**，每次都改图（粘走、印、开门） |
| 姿态变化 par | 3–4 | 6 / 5 / 6 |
| 解里**不在任何视图上**的一步 | 0（只有"我在哪一页"1 bit） | 暗一 1、暗三 1（**石背**：站到左页石头正上方的右页格再合——那一叠在叠合图上是 `#`）；暗二 0 |
| 位置依赖的盖印 | 无（`stamp` 不看人） | 暗三：站在墨上合，你落在印出来的那一面 |
| 一眼测试（一眼 / 两眼） | hard 6 关 2/2；final 1/2 → 2/2 | 暗一 0/2 → 1/2；暗二 2/2；暗三 0/2 → 0/2 |
| `check.js` v3 门禁 | len 16–20 · wrong 12–17 · dead 22–55% | len 19–22 · **wrong 11 · dead 16–26%**（按门禁反而**更弱**） |

结论不含糊：**我们的门禁偏爱的量（wrong、dead%）和人的难度负相关；人卡住的那一类东西（规则后果、多次改图、位置依赖）门禁一项都不量。** 暗二能一眼破，正因为它的"乘着影子合到底"在 VIEW 2 的 30° 列里是 ▒（影子落到纸上），读者直接读出；暗一、暗三的"石背"在任何视图上都是 `#`。读者 A 两眼之后写对暗一时，trick 一栏写的是「A closed stack you are already standing in is not blocked」——他必须**推出一条规则后果**才过得去。这就是靶心。

## 2. v3 设计原则：把难度从棋盘事实挪到规则后果

借的是 Stephen's Sausage Roll（每一格都有用、动作不可逆、同一物件用两次）、Baba Is You（规则是状态）、Monument Valley（视角改变连通性）、A Good Snowman（顺序错了就得重来，但错在三步之后才看得见）、Patrick's Parabox（你在容器里，容器也是格）。每条给一个《折信》的具体做法，并标出一眼测试会怎么判。

**P1 · 行动才揭示的信息（Parabox / 墨晕）** —— 不是雾，是**派生状态**：看一眼得不到，做一下才有，而做了就留下痕迹。
- **石下**：左页石头底下可以压着东西（钥匙 / 墨 / 胶），胶把石头粘走之后才露出来。`levels.js` 记法 `under: { '2,5': 'k' }`，`logic.js` 的 `stamp()` 在 glue 事件里把 `put(s, b, r, under[b,r] ?? '.')`。读屏：「石头底下压着东西」（不说是什么）。一眼测试：VIEW 4 会印出露出来的东西——所以石下必须配 P3（露出来的那样东西要在**第二次**盖印里才起作用）。
- **第三页只在翻过去那一拍才定**：翻 = 盖印，让 T 的内容依赖第一合（第一合把墨印到 R 的某格，翻过去时 R 的墨印到 L——"背面的字透过来"真的透过来）。一张 VIEW 6 不够，得按合的次数各印一张；人要在脑子里算两步。
- 不做：真正的隐藏格、随机。

**P2 · 不可逆与承诺（Sausage Roll / Snowbird）** —— 现在的死局都在第一个决定之后一步就看得见（VIEW 3 一行字）。要的是**三步之后才知道错了，而且错的那三步每一步都像对的**。
- 度量：`deadDepth`（进入死局到死局**可见**——没有任何合法的铰链动作还能改变棋盘——之间的最少动作数）≥ 3，且死局里仍有 ≥ 6 个"像有用"的合法动作。`gen.js` 现成有 `deadEnds`，加这一项。
- 具体：胶一次性。第一合用掉了唯一能造影子的胶，但合完之后你还能在叠里走四格、还能翻、还能斜起看到别的影子——都走得通，只是都到不了。暗三第一合是这样：站错格合上，墨照样印、石头照样走，你在叠里走得欢，三步后发现落在了墨印的另一面。
- **乘影即承诺**（暗二）：踩上影子之后角度只能单向走到底，中途没有纸可落。配上"合到底那一拍门开"，一次承诺买三件事。

**P3 · 顺序相关的机制交互（Baba）** —— 两条规则在同一格相遇，而且**谁先谁后结果不同**。
- **翻的链式盖印**（`design-ch6.md` §1.2 已有规则，还没用）：L 的胶 a 对着 T 的石头，R 的胶 b 对着 L 的同一格。先合（R 压 L）：b 对着的是空格，什么也不发生；翻（T 压 L）：a 把 T 的石头粘到 L；翻回来（R 压 L）：b 把它从 L 再粘到 R。**翻两次和翻一次的棋盘不同**，石头走了一条三页的路。VIEW 5/6 只印一次翻；人得算第二次。
- **墨 × 影**（第七章主菜，见 §4.2）：墨印到缺口上，缺口变纸——**纸上的影子不载人**。多合一次把你要乘的影子底下的缺口印成了纸，渡船就沉了。先乘后印 vs 先印后乘，只有一个顺序成立。
- **钥匙被胶粘不走，但门会被石头盖住**：石头粘到门的对面 → 那一叠 `#`；要先开门再粘。

**P4 · 似是而非的假路（Monument Valley 的错视）** —— 假路必须是**真规则的真后果**，而且在最像正解的那个视图上**看起来通**。
- **叠合图上通、走进去才断**：一条叠合路在 VIEW 3 连着，但走到中途那一叠两面都是纸（你留在原页），再下一叠只有另一页是纸——按规则你进不去。这是 `land()` 的后果，叠合图（只画 top/under）不显示。`gen.js` 加 `pathIllusion`：叠合图的 4 邻连通分量里 BFS 可达 vs `neighbours()` 真可达的差集 ≥ 2 格。
- **两道影子同列差一行**（5-7 已有雏形）：错的那道也能走，走到头是一格纸的孤岛，三步之后发现回不去（P2）。
- **第三页的终点在两叠都通的位置，但只有一叠的历史让你落在 T 上**。

**P5 · 啊哈 = 玩家还没注意到的规则后果（Sausage Roll 的"原来香肠能这样"）** —— 规则一条没加，但每关要求你从已知规则里推出一条**没在任何教学关演示过**的后果。这是暗一 / 暗三卡住主人的那一类。清单（每条只用一次，用过就进下一章的教学关变成常识）：
1. **石背**：站在左页石头正上方的右页格合书，你就在一叠 `#` 里，能出不能进（暗一、暗三、4-4 已用——但 4-4 的叠合图上那一叠是**唯一**没堵的，等于写在脸上）。
2. **站在胶上合 = 被粘上来的石头压死**（5-4 用过），反过来：**站在胶上翻**——T 对面的石头粘上来，你死；但 R 对面是空的话翻过去安全、翻回来死。
3. **翻被压 = 整关重来（格子复原）**：故意翻一次被压，把被胶搬走的石头搬回来——重来是一种撤销不了的"撤销"（`restart` 把 grid 复原）。只给暗信用。
4. **纸上的影子不载人**（6-5 盲测 G 的误解）：正解要你站到影子**跨过纸的那一格**再合，纸格把你留下。
5. **叠合里换页只在"恰好一面是纸"的叠**：同一条叠合路走两遍，起点页不同终点页不同——第二遍要绕一格去换页。
6. **合上时终点 G 在对面也算到**（`isWin` 的第二条）：G 被 T 的石头盖着时站进那一叠即赢——前提是石头先被粘走（P1 石下 + P3）。

**P6 · 多目标与顺序约束（Cosmic Express）** —— 一次盖印要同时满足两件事，或者两件事必须按固定顺序发生。
- **开门 + 搬石 + 不压人交在一格**（暗二已有）。
- **两封信**（故事上成立：卷二是"信写到了背面"）：G 和 G′ 各在一页，先到 G 之后 G′ 才出现（`isWin` 改成序列）；到 G 的那一合把到 G′ 的路粘断——所以要先把 G′ 的路铺好再去 G。读屏：「信有两页」。
- **翻的次数 = 资源**：翻一次能看 T，翻两次棋盘变（P3 链式）；par 4 里翻占两个，合和乘影只剩两个。

**每关自审清单**（取代 `design-ch6.md` §4 的"为什么不能 30 秒蒙出来"）：① 解里哪一步**不在 `glance.js` 的任何视图上**？说不出来 = 这关是读图题。② 第一个死局进入点之后，还要几步才看得出来？< 3 = 没有死局。③ 棋盘改变几次？< 2 = 一张图就够。④ 用了 P5 清单的哪一条？（hard ≥ 1，final ≥ 1 且 P3 ≥ 1，暗信 ≥ 2）。

## 3. 新门禁：视觉采样器 + 一眼测试

### 3.1 工具：`tools/glance.js`（已进仓库）

```
node tools/glance.js <id>                 一张"一眼纸"：人十秒内免费能看见的全部视图（§1.1 表）
node tools/glance.js --prompt <id>        给一个新模型的完整一次性提问：规则 + 一眼纸 + 答案格式
node tools/glance.js --verify <id> "walk 6,5" "fold 0" …   把答案的路线重放进 play.js：SOLVED / not
node tools/glance.js --all --chapter 5,6  一章的全部一眼纸
```

一眼纸的内容（全部物理角、1 起数的列行、和屏幕 / `play.js` 一致）：VIEW 1 摊平；VIEW 2 **七个采样角的左页并排**（░ 缺口上的影子 / ▒ 纸上的影子）；VIEW 3 合上——哪几格合会被压、盖印做了什么、**叠合图**（每叠 `上/下`，# 堵）；VIEW 4 / 4b 盖印后的图和新影子；三页关加 VIEW 5（翻——翻会压哪里、翻的盖印、翻后的叠合图）和 VIEW 6 / 6b（翻过去打开、翻过去斜起）；如果再合 / 翻回来会改图，加一句。规则文本写的是"通过卷一 + 本章教学关的玩家知道的"，包括 10/24 盲测补上的层规则和「纸上的影子只是纸」。**不给提示、不给关名之外的文字**（关名和一句话给，因为屏幕上有）。

**为什么这比 `play.js` 更接近人**：人读的是并排的、已经算好的视图，不是顺序的文字；`play.js` 的调用次数量的是读图接口的摩擦（§1.3）。两个工具都保留——`play.js` 查文案 / UI 困惑，`glance.js` 查难度。

### 3.2 协议与阈值

- **读者**：每关 **2 位**独立的新模型（Agent，sonnet），只许读那一个提示文件，无工具、无反馈，一次写出完整路线（≤ 14 行动作）+ 一句 trick + 信心。
- **判定**：`--verify` 重放，`*** SOLVED ***` 即"一眼破"。失败者给**一次**第二眼：把 `play.js` 的日志（游戏里真会显示的那些字）发回去，再写一次。
- **阈值**（按声明档位；"n/2" = 两位读者里一次写对的人数）：

### 4.2 第七章「墨晕」：从第一关起按 v3 设计

机制（`objects.md` B.2 #4、`roadmap.md` §4 #4）：湿墨 `I`。合上时像墨 `i` 一样印到对面的缺口；**之后每再合一次，已印出的墨向四邻的缺口洇一格**（石头、门、页边挡住；不洇到纸上——纸上本来就能走，洇了没意义；洇到胶上把胶盖住，胶失效）。一句"纸会怎样"：**墨还没干，每合一次洇一圈。**

为什么它天生是 v3 的料：

| v3 原则 | 墨晕怎么做到 |
|---|---|
| P1 行动才揭示 | 洇几圈取决于你合几次；一眼纸能印"合 1 次 / 2 次 / 3 次之后"的三张图，但你要**在哪一次合之间**走哪段路才是题——图上没有 |
| P2 不可逆 | 墨永不收回。多合一次，你要乘的影子底下的缺口变成了纸——**纸上的影子不载人**（P5-4），渡船沉了，而且三步之后才发现（`deadDepth`） |
| P3 顺序 | 先乘后印 vs 先印后乘；墨洇到胶上 → 胶失效 → 石头不走 → 影子不来。三条规则在一格相遇，顺序决定结果 |
| P4 假路 | 第一圈墨铺出一条看起来直通 G 的路，第二圈把它接上——但第二圈也把你的落脚缺口填掉；真路是在一圈和两圈之间走完 |
| P6 资源 | 合的次数第一次成了资源（par ≤ 4 里合 ≤ 3——本章把 `CLOSES_MAX.main` 放宽到 3，roadmap §4 已预告） |

**七关曲线**（草案；全部先过一眼测试再出设计稿 `design-ch7.md`）：
7-1 teach「湿」：一滴湿墨，合两次才接上路（≤ 30 s，一眼 2/2）。7-2 easy「晕」：合三次洇到门口，但第三次把你站的缺口影子填掉——第一次见"墨沉渡船"，一句话提示。7-3 mid「圈」：一圈够、两圈多——先乘影再合第二次。7-4 hard「胶与墨」：墨洇到胶上胶失效（P3），一眼 0/2。7-5 hard「两圈之间」：P4 假路。7-6 hard「翻墨」：翻 = 合，墨在 L–T 之间也洇，三页三张图。7-7 final「干」：合三次、翻一次、乘影一次，par 4；G 在 T，只有洇满两圈且第三合站在石背上才到——P1 + P2 + P3 + P5-1，一眼 0/2、两眼 0/2 才算 final。暗信：P6 两封信 + 石下。

**第七章的生产门禁顺序**（roadmap §3 的八步，第 3 步替换）：规则进 `logic.js`（`stamp()` 加 `bleed` 事件；状态键里网格链已经能编码洇的圈数）→ `gen.js` 搜（`--need ink+shade`，适应度加 `phases ≥ 2`、`deadDepth ≥ 3`、`hidden ≥ 1`）→ **一眼测试 2 位读者**（hard 0/2、final 0/2·0/2）→ 主人计时 → 设计稿 → 文案（关名是物件：湿、晕、圈、干；不许出现"先""再""别"）。
