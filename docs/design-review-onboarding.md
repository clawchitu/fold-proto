## 2. 给建造者的修改单（照做即可，不用再看帧）

### 2.2 笺

- **F2** 笺名旁的图标 = 棋盘上同一张皮的 tile 图（稿 §2.1）。三张没有 tile 的规则笺，图标定为：**压** = 石墩 + 下方一道短横线 + 向下短箭头（A12 的画法，采纳）；**乘影** = 交叉线方格上一个墨点纸人（A12 的画法，采纳）；**第三页** = 两张错开叠着的页（A12 的画法，采纳）。**纸片**的图标改为跨缝成对的 V 折（棋盘 tab 的图），不是文档图标。

## 4. 三个待裁定问题，我定了

1. **老玩家**：按稿 §4 第一行——播种为已见 + 「物件」页 + 回到地图时一条一次性的「书里夹了几张物件笺 ›」。理由不变：打完 42 关的人不该连吃六张笺；他要认胶，去「物件」页点一下就是那张动的笺。
2. **折数进 1.0：做。** 成本确实小：`levels.json` 每关已有 `expect.changes`（= 标准折数，求解器算的姿态变化数），App 已经收到每一次 `.postureChanged` 事件。建造：`GameModel` 从 `go()` 起数姿态变化（压回起点不清零，重来 `restart()` 清零），过关时 `bestFolds[id] = min(old, n)`；存 `fold.bestFolds: [String: Int]`（`SavedProgress` 新增 key，`reset()` 一起清，`migrate` 不碰它）。章页行末「折 {n} · 标准 {par}」只在 `bestFolds[id]` 存在时出现；等于标准时 ✓ 旁加 3 pt 小点（B1 / B2 的画法，采纳）。老玩家已送达的关没有记录 → 只画 ✓，重玩一次就有了——不回填、不猜。「折」= 姿态变化次数，含翻（`check.js` 的 par 口径）。
3. **点卡片 → 章页：定。** 「继续」是快路，章页是目录；长按菜单删。不再问。
