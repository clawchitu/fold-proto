# 《折信》设计评审 · 第三轮：折页的方向与相机（2026-10-17）

评审对象：TestFlight 0.1 (4) 的竖屏「相机书」（`letterfold/App/Sources/BookView.swift` 的 `BookCamera` / `CameraBook`），Shuai 的试玩反馈：「折纸的时候是朝我反方向折」——第一章全程，拖页时上页像是往屏幕里倒、向后仰，而不是像桌上的书那样朝自己合过来。
评审人：Fable（主设计）。依据：`plan.md` §12（Duo：动手机时手机就是那本书）、`design-spec.md` §0 / §4、`design-review-2.md` §4.1（90° 墙 + 45° 坡道、俯前视相机）、letterfold `README.md` 0.1 (2) 的「修正（评审后）」与 0.1 (4) 的相机书说明。
角度一律 **物理角**（180° 摊平、90° 立起、0° 合上）；代码里 `GameModel.angle` 仍是折角 `t = 180 − 物理角`，括注给出。

**总判断：上页必须朝观者折——从屏幕里出来，像把一页纸朝自己掀起、翻过来、面朝下盖到下页上。这不是改旋转方向，而是改相机。** 代码里的旋转本来就是朝观者的（下面 §1），Shuai 读反，是因为 review-2 §4.1 让相机的俯角跟着页角一起动。那条定稿在静帧上成立、在动态里不成立，本文撤回它：**拖页时相机不动；书立住之后相机才俯下来看墙。**

---

## 1. 诊断：方向没错，相机把它读反了

书空间（`BookCamera` 注释）：x 沿折痕，y 从折痕朝观者穿过下页，z 从桌面向上。上页沿 `fold = (0, −cos t, sin t)` 铺开：摊平时指向远处 (0, −1, 0)，90° 时竖直 (0, 0, 1)，合上时 (0, 1, 0) 躺在下页上。正面法线从 +z 转到 +y 再转到 −z，正面一直朝向相机，直到 `t > 90° + pitch` 才换成背面。这就是桌上一本书的谷折：书脊贴桌，上页的正面朝观者扫过来，最后面朝下落在下页上。方向对，和 Duo 的铰链一致（合手机时上半块屏幕是朝你的脸过来、再盖到下半块上）。

读反的原因有三个，都在相机：

1. **俯角跟着页角走（pitch = 16° + 24°·sin a）。** 页抬起时相机同时往下俯，下页从 0.96 H 缩到 0.77 H，上页也从 0.93 H 缩到 0.75 H——两页同步变矮、都成了梯形，没有相对运动。两张纸一起变矮，在平面屏上唯一的读法就是「整本书往后倒」。
2. **前 28° 页边往上跑。** 上页外缘在屏幕上的高度是 `H·cos(t − pitch) / w`。拖动开始时 t < pitch，这个值随 t **增大**：手指向下拉，页边向上走了约 0.09 H（≈ 30 pt），直到 t ≈ 28° 才掉头。玩家拉的第一下看到的就是反向运动。
3. **正面一直看到 130° 折角（物理 50°）。** 相机俯到 40°，一张「正面朝上、一直变矮」的纸看了 130° 之久。人对平面屏的先验是从正上方看桌面，面朝上还在变矮 = 盖子往后倒。真正的翻面（正面→背面）发生得太晚，没有在 90° 附近给出「它过来了」的那一拍。

0.1 (2) 的 README「修正（评审后）」写的是「竖屏下上页到 130° 前向后仰（远离观者），130°→180° 才翻过来」，那是按 v2-2 / a11y-c2 的静帧做的一个取巧；0.1 (4) 的相机书在几何上改对了，但观感上等于把这个取巧又演了一遍。两条一起撤。

---

## 2. 决定：方向

- **旋转轴 = 折痕（书空间 x 轴），方向 = 上页外缘先离桌向上、再朝观者过来、最后向下盖住下页。** 代码里 `fold = (0, −cos t, sin t)`、`FrontFace` 用 `(o: edge0 + H·fold, ev: −fold)`、`BackFace` 用 `(o: edge0, ev: fold)` 全部保留，一个符号都不改。
- **物理隐喻**：桌上一本翻开的书，书脊贴桌。你从下页这一侧看，伸手把远处那页朝自己掀过来。Duo 上就是合手机。
- **合上状态**：上页面朝下落在下页上，两页在屏幕上的四边形完全重合（同一台相机、同一组点），背面透出叠合后的地图（透光 0.15 的描图纸，review-2 §2.5 不变）。压下 2 pt、折痕发亮、「啪」不变。
- 横屏 / Duo 的竖折痕版本（`legacyBody` 的 `−va` 绕 y 轴、anchor `.leading`）本来就是朝观者翻（+z 出屏），不动；但 `legacyBody` 里横折痕那一支（`BookBody.tilt`：先后仰 62° 再翻过来）是 0.1 (2) 的取巧，删除。

---

## 3. 决定：相机

**一台相机、两个姿势、手指在屏上时绝不移动。**

| | 俯角 pitch | 侧转 yaw | 什么时候 |
|---|---|---|---|
| 手里的相机 | **12°** | 18°·sin a | 摊平、合上、第三章影子姿态、**所有拖动过程**（含铰链驱动） |
| 看墙的相机 | **40°** | 18° | 松手后吸附到 **90°** 并停住 |

- 切换只在 **没有手指在屏上、页已到吸附点** 时发生：松手且目标是 90° → 从松手那一刻起 320 ms ease-in-out 俯到 40°（页 160 ms 到位，相机随后 160 ms 收尾，和 Impact .medium、纸舌声、`crease.glow` 400 ms 是同一拍——「相机俯下来看墙」就是立住的奖励之一）；从墙上离开、松手落到别处 → 320 ms 回到 12°。手指或铰链一碰页，相机就冻结在当前值直到下一次松手。
- yaw 保留 review-2 的 18°·sin a（看墙时恒为 18°）：它只有横向分量，是正确的运动视差（墙顶相对墙脚侧移），不会制造「变矮」。
- **折痕在屏幕上永远不动**：`cx / cy` 继续以折痕为锚（现在 `cy` 取摊平参考框、`cx` 按当前框居中，不变）；相机切换绕折痕线进行。
- 透视 `f = 2.6·Hc` 不变（H / f ≈ 0.21）。它不是问题所在，远边宽 1.26× 已经够说「它更近」。
- `k`（整本书的缩放）仍按「摊平 @12°」和「立起 @40°」两个框一次拟合，页转时不缩放；两个框尺寸和现在几乎相同，格子大小不变。
- 减少动态效果：同样两个姿势，切换改为 200 ms 线性（和全 App 的减少动态规则一致），yaw 恒为 0。不再用固定 28°——固定一个中间俯角会让每次拖动的前 28° 都往上跑。

**上页外缘在屏幕上的位置**（相对折痕，以页深 H 为单位；正 = 折痕上方；后面的倍数是远边宽度 / 折痕宽度）：

| 物理角 | 折角 t | 手里的相机 12° | 看墙的相机 40° |
|---|---|---|---|
| 180° 摊平 | 0 | +0.94 H · 0.96× | （+0.68 H · 0.88×，只在从墙上拖开时经过） |
| 168° | 12 | +1.00 H · 1.00× ← 「离桌」的峰值，比摊平高 6% ≈ 20 pt | |
| 130° | 50 | +0.91 H · 1.15× 正面，向后斜立 | |
| 90° 立起 | 90 | +0.26 H · 1.26× 正面，薄薄一道墙 | **+0.77 H · 1.19× 正面，墙** |
| 78° | 102 | 0（翻面：正面 → 背面） | |
| 50° 影子姿态 | 130 | **−0.58 H · 1.23× 背面，雨棚** | 0（从墙上合下来时在这里翻面） |
| 0° 合上 | 180 | −1.02 H，与下页近边重合 | −0.89 H，与下页近边重合 |

读法：拖页时上页只有一次 20 pt 的「离桌」抬头，之后一路向下，78° 翻面，然后背面一路长大盖到下页上——就是 Flipboard 式的翻页，没有人会读反。墙在拖动过程中是薄的（0.26 H），立住以后相机俯下来，它才长成 0.77 H 的墙。

## 4. 决定：拖动怎么映射

现在的规则是「页外缘在**桌面**上的投影 1:1 跟手」（`panChanged`：`proj = d·cos(angle)`，`raw = acos(proj / d)`）。这是正上方视角的假设；相机一旦有俯角，手指和页边在屏幕上就会分开（90° 时差 0.25 d ≈ 80 pt）。改为：

- **抓点 G** = 上页上离折痕 d 的那一点（d 的取法不变：≥ 0.35 页深）。
- **t ≥ pitch 时：G 在屏幕上的 y 跟手 1:1。** 每帧解 `project(crease + d·(0, −cos t, sin t)).y = y₀ + Δy`，在 t ∈ [pitch, 180° + pitch] 这段单调区间上二分 20 次即可。
- **t < pitch 时：沿用桌面投影规则（acos）。** 从摊平开始拖，前 12°（12° 俯角下手指只走 0.02 d ≈ 7 pt）页边向上「离桌」20 pt，然后进入跟手段；从墙上往回摊平、相机冻结在 40° 时，最后 40° 页边自然躺下、手指继续向上走 0.23 d——这是「远处那页躺回去」本来的样子，允许。两段在 t = pitch 处连续，切换时重新取 y₀。
- 越界橡皮筋、松手按速度投射 0.12 s、吸附 180 / 90 / 50 / 0（折角 0 / 90 / 130 / 180）、15° 一下的触感、经过吸附点的 Impact——全部不变。
- 铰链、按钮、读屏控件直接写角度，不经过这条映射；铰链驱动期间相机同样冻结，停下 300 ms 吸附后再切姿势（plan §12.1 第 2、4 条）。
- 2-1 幽灵手：拖到 90° 停住、松手，相机随之俯下——教学里第一次出现「墙」就是带着这个运镜出现的。

## 5. 90° 与 50° 怎么读

**90° 立住（看墙的相机 40° / 18°）**：墙 0.77 H 高，4 行格子每行 ≈ 60 pt（≥ 44 pt，可点、可走），墙顶 1.19× 宽于墙脚；下页 0.89 H、近边 1.16× 宽；两片纸片在墙脚拼成 45° 坡道，坡面朝相机、亮面 + 横纹 + 两侧 V 撑；下页上从折痕向观者铺半页深的软影。这和 review-2 §4.1 的静帧是同一张画，只是现在它是**松手后**才出现的画。墙上被坡道顶部挡住的第 3 行那格、坡道厚度 0.35 格，仍按 review-2 在真机看。

**50° 影子姿态（折角 130；手里的相机 12°）**：上页已翻过面，背面向着相机，像一片雨棚从折痕伸出来盖住下页上半 0.58 H，远边 1.23× 宽。隔着描图纸看到下页的路和石头，纸人的影子落在棚下的下页上。这是第三章「影」在物理上该有的样子：光从上页背后来，透过纸把影子投到下页——review-1 §2 「像打开一张立起的贺卡、向后仰」那句改掉：**是雨棚，不是贺卡。** 第三章在 M4 出稿时按雨棚画，91°–154° 的影子窗口（物理 26°–89°）不动。

物理 130°（折角 50）只是路过：上页正面朝上、向后斜立 0.91 H 高、顶边 1.15× 宽——顶边比折痕宽，所以读得出它是**立起来靠近相机**，不是倒向远处。

## 6. 其他

- 明暗不改：上页正面 `0.13·sin a` 的受光、下页从折痕铺开的软影、合上时 `0.12·sin t` 的压暗，继续做「它朝我过来了」的第二层线索；主线索是 §3 的相机。
- 读屏与点击目标（`ProjectedTargets`）每帧按当前相机生成，相机切换 320 ms 期间目标跟着走，和现在一样。
- 横屏 iPad（非 Duo）仍是 `legacyBody` 的侧翻，90° 时墙是一条线；第二章在 iPad 横屏上不可玩。M4 让横屏也走相机书（竖折痕、同一对姿势、俯角换成侧转），本次 TestFlight 不做。Duo 上立起的页就是物理上半块屏，不需要相机。
- letterfold `README.md`：删 0.1 (2) 「上页到 130° 前向后仰」那条修正；0.1 (4) 的相机书说明改为本文 §3。`design-review-2.md` §4.1 / §6 第 4 条：俯角公式由本文取代，yaw 与坡道厚度保留。

## 7. 构建步骤改动清单（0.1 (5)）

1. `BookCamera.make`：`pose(a)` 不再返回随 a 变的 pitch；pitch 由 `GameModel` 的相机状态给（12° / 40°，320 ms ease-in-out；减少动态 200 ms 线性），yaw 仍 18°·sin a（减少动态 0）。`k` 的两个拟合框改为摊平 @12° 与立起 @40°。
2. `GameModel`：加相机姿势状态；`arrived(at:)` / `move(to:)` 目标为 90（折角）且无手指时切到「看墙」，离开 90 并松手后切回；`dragBegan` / 铰链接管时冻结。
3. `BookView.panBegan / panChanged`：§4 的两段映射（t ≥ pitch 屏幕跟手，二分求逆；t < pitch 沿用 acos）。
4. 删除 `BookBody.tilt` 与 `legacyBody` 横折痕分支。
5. README 与 design-review-2 的交叉更正（§6）。
6. XCUITest：真拖页用例不改断言（吸附值不变）；加一条「从摊平拖 40 pt 后上页外缘的屏幕 y 不高于起点 + 24 pt」的截图断言，防止再回到抬头。

## 8. 验证

0.1 (5) 发给 Shuai 只问一句：「现在折的时候，纸是朝你过来的吗？」不解释、不提示。另两件在真机看：① 立住后 320 ms 的俯下是否像「奖励」而不像「晃」；太晃就缩到 240 ms，不要去改俯角；② 从墙上往回摊平的最后 40°（相机冻结在 40° 时页边躺下、手指继续上走）是否被当成 bug——若被两位以上测试者指出，改为松手回摊平时相机先回 12° 再让页躺下（即把 §3 的「冻结」在这一个方向上放开）。

**GO。** 方向不改，相机改成「拖时不动、立住再看」，映射改成屏幕跟手。
