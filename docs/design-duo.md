# 《折信》iPhone Duo 支持设计稿（2026-10-30，1.0 范围；2026-10-31 改为「铰链不是输入」）

依据：`plan.md` §12（原：铰链是并行的第二输入）、`design-spec.md` §4/§5 `hinge.device`、`design-ch12.md` §1、原生 `App/Sources/Hinge.swift` / `GameModel.hingeMoved` / `BookView`。主人拍板：**Duo 支持进 1.0（只发 iPhone，无 iPad）**。

> **决定（2026-10-31，真机 build 28 测试反馈 → 主人拍板）：撤掉「铰链折页」。** Duo 上的两块屏都是普通 iPhone：只有手指拖页和点格。内屏是一本更大的、左右翻的书，书脊落在物理折痕上，但手机开合**不再**改变纸的角度。原因（测试者原话加几何事实）：
> 1. 「我展开 / 折叠手机，你不需要在游戏里也折纸吧？」——玩家把手机开合当成**换屏**，不当成折书；每次换手、搁桌、拿起都动了纸，像误触。plan §12 说「游戏永远不要求它」，可只要它在，它就在替玩家做决定。
> 2. 影子章节的角度窗口（物理 26°–89°，压缩后 ≤ 67°）等于让人**把手机合到只剩一条缝的时候盯着内屏看**，而 4-4 要停在 60° 左右（物理）再细调 ±5°。拇指在玻璃上能做的，手腕夹着一台半合的手机做不到。
> 3. 两屏看起来是两盘不同的棋（内屏按相对角画、外屏按绝对角画；§1 的映射和停下吸附让虚拟角 ≠ 物理角）。测试者 3-3、4-4 两次卡在「外屏能走到影子下、内屏不行」。
> 4. 这一套（接管 / 追上 / 空闲 / 吸附 / 相对角 / 盖子画法 / 十二章 face 规则）是全项目最大的一块只能真机验的代码，换来的是一个没人要的输入。
>
> 下文 §1–§4 是定稿；原 §1「映射」、§3「并存」、§4「十二章铰链」、§5 边界表里所有铰链行、§6 参数表与 S3–S12 用例**全部作废**，留在 git 历史里（`git log -- docs/design-duo.md`）。`plan.md` §12 的「并行第二输入」从此只是候选，不在 1.0。

角度写法：**物理角** θ = 180° 摊平、0° 合上；**折角** f = 180 − θ（FoldCore / `GameModel.angle`，0 = 摊平、90 = 立起、180 = 合上）。1.0 里物理角只出现在 §0 的事实里，规则和渲染都不读它。

## 0. 事实（SDK 27.1 头文件、模拟器机型、真机 build 28）

- 模拟器「iPhone Duo」（iPhone19,4，iOS 27.1）：内屏面板 2007 × 2853 @3x，`nativeRotation 270` ⇒ 只支持竖屏的 App 在内屏上是 **951 × 669 pt 的横向窗口**（真机截图 2853 × 2007 证实），铰链在窗口里是**竖线 x = 475.5 pt**；外屏 1398 × 2034 @3x = **466 × 678 pt**，普通 iPhone。内屏遮罩是整块圆角矩形，没有铰链缺口。合上 ⇒ 系统把 App 交到外屏；打开 ⇒ 回内屏，窗口重建，场景不重启。
- `UIHinge` / `UIHingeInteraction`（status + 弧度角）存在，但 1.0 不再使用。**不读角度、不读 status**，不做铰链几何推断（折痕位置靠窗口长边 / 2，和 build 28 一样可靠）。
- 真机外屏（466 × 678）和普通 iPhone 一致：横折痕居中、12° 手持相机、雨棚。build 28 的 3-3 / 4-4 都能在外屏打通；内屏打不通的原因见上面第 3 条和 §3。

## 1. 内屏 = 书脊握法，纸不跟手机动

- **方向**：窗口宽 ≥ 高 × 1.15 ⇒ 竖折痕（左右页）；否则横折痕（上下页）。这是 `BookView` 现有规则，内屏自然落到竖折痕。**左页固定（地图第 3→0 列），右页是折页（第 7→4 列），拇指按住右页外缘往左拖**——和竖屏手机「上页向下合」是同一个动作转 90°，不加新布局、不加提示。
- **钉**：竖折痕时折痕线 := 窗口宽 / 2（屏幕坐标，= 铰链 x 475.5），只在短边 ≥ 600 pt 的窗口成立。保留的理由只有一个：书脊画在离真折痕 20 pt 的地方会像 bug。外屏和普通 iPhone 照旧居中。UI 测试 `probeCreaseX` 断言 |creaseX − 475.5| ≤ 1。
- **格子**：80 pt（5 行地图 5 × 80 + 16 + 20 = 436 < 669）；十二章三折右半放右页 + 第三页 ⇒ tile 45、pad 6（8 × 45 + 48 = 408）。左页同格。
- **相机与画法：和外屏完全一样。** 12° 手持相机、拖动中相机不动、斜起是雨棚从折痕伸出盖住左页外侧、合上画在固定页上的描图纸（review-3 §closed）。**画出来的折角 = 虚拟折角**（删掉 `drawnOffset` / `physicalFold` / `dragLid`，删掉内屏 pitch 0 的分支、删掉「铰链合上的书画在下半屏」）。手机半开着看内屏时，纸就是画在一块弯着的玻璃上的一本平书——接受，不做任何补偿。
- **顶栏、笺、读数、页脚**：按横屏窗口正常排（顶栏在上、页脚在下，横跨两半）。不再有「盖子只放纸」的限制。
- **十二章**：书的折痕和第三页的折痕都归拇指（`switchCrease` 照旧）。删掉 `tri.hingeIsBook` 这条规则和文案。

## 2. 换屏

| 情况 | 行为 |
|---|---|
| 合上手机（内 → 外） | 系统换屏。关卡状态、虚拟角、撤销栈、朱线全部不变；外屏按横折痕重排，**不**因为合上而把书合上 |
| 打开手机（外 → 内） | 同上反向。钉回 475.5，页角不变。不播任何音、不做过渡动画（窗口是系统重建的，我们做不了跨屏动画） |
| 换屏时正在拖页 / 动画中 | 触摸序列被系统打断 ⇒ 走现有 `release` 吸附；动画 `finishMotionNow` |
| 换屏时「啊哈」中 | 跳到最后一帧（现有规则） |
| 设置「铰链折页」 | **删除**。`hingePresent` 恒 false；`set.hingeHintSeen`、`duo.hint`（「也可以把手机合一点。」）一并删 |
| 后台 / 前台 | 普通 iPhone 规则，无铰链相关处理 |

## 3. 4-4「石雨」在内屏走不到影子格的根因（build 28，和铰链无关，**仍要修**）

外屏雨棚盖住下页上部 0.58 H，影子格大多露在雨棚边缘之外，点得到；内屏竖折痕的雨棚从折痕向左伸出，**整列盖住**左页第 3 列，被盖住的格子只在 `overlay: .squares` 那一层重画（`TileLayer(... interactive: false, veiled: true)`，`BookView` 约 850 行），点击落到上页的拖页热区，所以「走不过去」。规则层没错，是输入层：

- **被盖住的格子要能点。** 上页热区里的一次**点击**（没有位移）如果落在固定页某格的投影上，就是 `model.tap(c)`；拖页只在位移 ≥ 6 pt 后开始（现有 pan 已经有这个阈值的话就只差把 tap 转发）。横折痕同样适用（3-2、4-1 雨棚下的格子今天也点不到，只是没人撞上）。
- **被盖住的影子格要和露在外面的一样显眼**：按 review-ch3 §4 ②，格子、影子、纸人在最上层，只蒙 15% 薄纱。内屏截图里影子格比外屏暗得多，查一下竖折痕路径是不是把雨棚画在了 overlay 之上。
- 验收：`DuoUITests.testInnerBookSpinePlaysFourFour`（拖页到 125–135、点被雨棚盖住的（3,2）、走上去、开到 105 乘影到（3,2）、下墨、到终点）。
