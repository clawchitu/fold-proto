# 《折信》iPhone Duo 支持设计稿（2026-10-30，1.0 范围）

依据：`plan.md` §12（铰链是并行的第二输入，游戏永远不要求它）、`design-spec.md` §4/§5 `hinge.device`、`design-ch12.md` §1（两道折痕一次只动一道）、原生 `App/Sources/Hinge.swift` / `GameModel.hingeMoved` / `BookView`。主人拍板：**Duo 支持进 1.0（只发 iPhone，无 iPad）**。结尾那句「等 Duo 到了，用真的折痕再玩一次」要兑现：手机的铰链就是书脊。

角度写法：本文**物理角** θ = 180° 摊平、0° 合上；**折角** f = 180 − θ（FoldCore / `GameModel.angle`，0 = 摊平、90 = 立起、180 = 合上）。

## 0. 事实（SDK 27.1 头文件、模拟器机型、现有代码）

- `UIHinge`：`status`（unknown / closed / partiallyOpen / fullyOpen）+ `angle`（**弧度**，更新频率与精度是系统策略，不能依赖）。`UIHingeInteraction(updateHandler:)` 加在任一 view 上；首次调用给初始状态；`update.hinge == nil` = 这个 view 层级不提供铰链（离开了提供铰链的窗口）；`isEnabled = false` 时不排队，重新开启时立刻给当前状态。**没有铰链几何 API**（没有 display feature / hinge rect），**`simctl` 没有铰链命令**，只能在 Device Hub 里拨。
- 模拟器「iPhone Duo」（iPhone19,4，仅 iOS 27.1）：内屏 2007 × 2853 @3x = **669 × 951 pt，竖屏原生**（`nativeRotation 270`）；外屏 1398 × 2034 @3x = 466 × 678 pt。内屏遮罩是整块圆角矩形，没有铰链缺口。折线把长边对半分：**App 是竖屏（`UISupportedInterfaceOrientations: Portrait`），所以窗口里铰链是一条横线，在屏幕 y = 475.5 pt**——正好是现有竖屏「横折痕、上页向下合到下页」的布局。模拟器开机是合着的（status = closed，angle = 0）。
- 现有代码已做：`UIHingeProvider`（π = 摊平、0 = 合上的标定假设）、`hingeMoved`（300 ms 内 ≥ 8° 接管、160 ms 追上、物理 30°–90° 压到折角 90°–180°、停 300 ms 后交回并 `restTarget` 吸附、每次接管一步撤销）、设置「铰链折页」（`hingeFold`，默认开，只在 `hingePresent` 时出现）。**本文纠正一条**：`GameModel` 375 / 1293 行和 `BookView` 100 行「有铰链 ⇒ `.verticalCrease`」是错的——铰链在竖屏窗口里是横的，布局只看窗口长宽比；README 第 65 行「Duo 上铰链是唯一输入」早已被 plan §12 取代，一并改。

## 1. 映射：铰链角 → 书的折角

**握法（1.0 唯一支持的）：翻盖。** 下半屏托在手里或放桌上 = 左页（固定页，地图第 3→0 列）；上半屏是盖子 = 右页（折页，地图第 7→4 列），合盖 = 合书，列 c 落到 7 − c。方向和竖屏手机完全一致，没有新布局。书脊握法（横屏、竖铰链、左右页）见 §7「以后」。

| 物理角 θ | status | 折角 f | 说明 |
|---|---|---|---|
| fullyOpen（任何 θ） | fullyOpen | 0 | 真机最大开角可能 < 180°；状态说摊平就是摊平 |
| 172°–180° | partiallyOpen | 0 | 摊平死区 `flatDead` 8°：搁在桌上的微抖不算折 |
| 90°–172° | partiallyOpen | 180 − θ | 原样 |
| 30°–90° | partiallyOpen | 180 − (θ − 30) × 1.5 | `shut` = 30° 的压缩段（plan §12.1 第 3 条）：「啪」在内屏熄灭前发生 |
| ≤ 30° 或 closed | closed | 180 | 合上。真的合到底：熄屏即合上，再打开时播「打开 · 路已接通」那一拍 |

- **平滑**：不滤波。接管后 160 ms 追上，然后 1:1；`FoldGame.setAngle` 的子步（≤ 5°/步）保证稀疏更新也经过每一个 90°（滚）和 179.5°（相触）。真机若静止抖动 > 0.5°，再加一阶低通（`jitter`，§6），现在不加。
- **姿态**：FoldCore 规则照常读**虚拟折角**（`popMin 60 / popMax 120 / foldMin 155 / shadeMin 91`），不加滞回；手停在阈值上的闪烁由下一条的停下吸附解决，真机验（§6）。
- **吸附与磁吸，永远不和手较劲**：铰链在动时**不吸附、不橡皮筋、不播 Impact**（铰链本身就是触觉），只留 15° 一下的 Selection tick 和相触的「啪」（`CloseFeel` 按角速度）。铰链停下 300 ms：虚拟折角走到 `restTarget`（一二章 0 / 90 / 130 / 180 最近点；三章起锁定窗口中点、自由斜角原地不动、≥ foldMin 合上）。**吸附只改规则读到的角和影子（≤ 5°），不动纸**——因为纸画在玻璃上（§2 相对角），物理半屏不会被我们转。虚拟角和物理角从此允许不同，直到下一次 ≥ 8° 的转动把它追回来。
- **谁最后动谁说话**（plan §12.1 第 1 条不变）：手指按着页、按钮、读屏动作随时收回页；`hingeActive` 期间点格走路要等停下吸附（`finishMotionNow`）。

## 2. 内屏布局：折痕钉在铰链上

- **钉**：`y_hinge = windowScene.screen.bounds.height / 2`（屏幕坐标，不是安全区的中点——上下安全区不对称），换算到 `BookView` 坐标后，`y0 + page.height`（折痕线）:= `y_hinge`。只在「有铰链 + 窗口宽 ≥ 600 pt（内屏）」时钉；外屏和普通 iPhone 照旧居中。UI 测试已有 `probeCreaseY`，断言 |creaseY − 475.5| ≤ 1。
- **盖子只放纸**：Duo 上顶栏（「书」「?」）、笺、角度读数、页脚按钮全部移到**下半屏**；上半屏从安全区（≈ 59 pt）到铰链都是折页。下半屏 ≈ 475 − 34 pt，一页 4 格 + 控件绰绰有余。
- **格子**：普通章 4 行 / 5 行地图都用 **80 pt**（竖折痕时行是横向的，5 × 80 + 16 + 20 = 436 < 669）。十二章三折：盖子要放两页高（右页 + 第三页，远离折痕方向），412 pt ⇒ **tile 45、pad 6**（8 × 45 + 24 + 24 = 408），≥ 44 的触控下限刚好；左页同格。
- **相机 = 玻璃上的纸**：Duo 内屏**始终** pitch 0、yaw 0、不看墙（40° 那档不用）——盖子立起来，它自己就是墙。**画出来的折角 = 虚拟折角 − 物理折角**：铰链驱动时两页都平贴各自半屏（相对角 0），只有影子爬过来、折痕发亮、纸面下压这些会动；手指在摊平的手机上拖页，相对角 = 虚拟角，和手机一样翻；手指在半开的手机上拖，页相对盖子再翻那一截。过了 90° 盖子背对人：**铰链合上的书，叠起来的地图画在下半屏（固定页区域）**，手指在摊平手机上合的书照旧画在上页背面。这是 1.0 最大的渲染决定，真机看一眼（§6）。
- **摊平 vs 半开**：摊平（fullyOpen 且静止）= 一台宽 iPhone，上述钉和平视相机仍成立（相机不切换，少一次过渡）。半开 = 盖子是页。没有第三种状态。
- **外屏（合着）**：系统把 App 交到外屏（466 × 678）时，它就是一台普通 iPhone：横折痕居中、不钉、铰链不是输入（status closed ⇒ 已是 180）、拖页照常。不做外屏专属模式。再打开回内屏：钉回来，虚拟角不变，**不**因为打开本身而摊平——等下一次 ≥ 8° 的转动。

## 3. 模式与并存

- **铰链只在 partiallyOpen 且在动时是输入**（8° / 300 ms 门槛不变）。fullyOpen 静止、closed：只有手指。`hingeFold` 关：`interaction.isEnabled = false`，布局仍钉（半开的手机仍然该在铰链处有折痕）。
- **拖页永远在**（整张上页是热区）；按钮行、读屏转子、切换控制照旧——五种输入写同一个角（plan §12.5）。
- **减少动态效果**：铰链照样驱动（动的是用户自己的手，我们没加动效）；160 ms 追上改成直接 `setAngle`，停下吸附改成 200 ms 线性淡影子（已有 `motionReduced` 分支）。
- **VoiceOver**：停下吸附后的一句 `settle` 公告不变；接管时**不**另外报「铰链在折页」（会和角度公告打架）。盖子上没有控件，所以转子顺序不变。
- **第一次发现（安静的一句）**：Duo 上、**1-2**（1-1 归幽灵手）、手机摊平、玩家已用拇指折过（`hasFolded`）、从未用铰链折过：书下方淡入一行「也可以把手机合一点。」（en “You can also fold the phone a little.” / ja・ko 走词表），6 s 或铰链一动就淡出，**一装机一次**（`set.hingeHintSeen`）。VoiceOver 下改成公告一次。不弹窗、不教学。plan §12.2 的四个「签名时刻」只是偏好，铰链版幽灵手留到以后。
- **设置**：沿用「铰链折页」开 / 关（默认开，只在 `hingePresent` 时出现）。不加第三档、不加灵敏度滑块（阈值在 §6 表里，真机标完就定）。

## 4. 十二章：铰链只折一道折痕

- **铰链 = 书的折痕（face 0 / 3）；第三页永远是拇指折的虚拟页**（roadmap §4 #2：「手里的书和屏里的书第一次不一样，本身就是题」）。face 0 盖子上：右页贴着铰链，第三页在它外侧（朝顶边），两页刚性一起抬（现有 `TrifoldPage .third`）。
- **face 2（第三页的折痕在手）时铰链怎么办**：转动 < 8° 忽略；≥ 8° 时看 `creaseBlock`——第三页**摊平或折到底**（block 为 nil）⇒ 自动 `switchCrease` 回书的折痕再接管（和 `autoCrease` 同一条路，一步撤销覆盖两件事）；第三页**半折**（`flapFirst`）⇒ 忽略，每关最多提示一次「第三页用手指折；铰链折的是书。」（新键 `tri.hingeIsBook`），不拒绝、不抖。
- **face 2 的画法**：左页留在下半屏原位、压暗（`aside`）；右页留在盖子上贴铰链、作为虚拟折痕的固定页；第三页绕右页的外沿虚拟翻折（它自己的锚点，不用 §2 的相对角）。不像手机上那样把三页重新居中——Duo 上纸不搬家。
- **折到底自动换回书**（design-ch12 §3.3 ④）不变；换回后铰链立刻有效。face 3 盖子 = 合成页（第三页在上、洞里看到右页），`offBook`、拒绝（`stone` / `cover`）全是规则层的事，与输入无关。

## 5. 边界

| 情况 | 行为 |
|---|---|
| 半开搁桌、点格走路 | 铰链静止 ⇒ 没有更新 ⇒ 手指是书；规则读停下吸附后的虚拟角。手持抖动靠 8° / 300 ms 门 |
| 撤销 | 恢复虚拟角，物理角不动（允许不同）；下一次 ≥ 8° 转动再追回。一次铰链接管 = 一步撤销 |
| 重开 | 非三折：重开后把物理角作为第一折套上（现有 734 行）。三折：先按规则摊平（face 0、f 0），再把物理角作为书的一折套上（face 0 合法） |
| 快合（一帧从 180° 到 closed） | `setAngle` 子步照样扫过 90°（滚一次）和 179.5°（「啪」一次，`CloseFeel` 取最后 80 ms 角速度）；一次接管一步撤销；结果在再打开时看（公告「打开 · 路已接通」） |
| 没有铰链 / `update.hinge == nil` / status unknown | 回 `SimulatedHinge`，`hingePresent = false`，设置项隐藏；布局按窗口：内屏仍钉（铰链几何不靠 API），外屏 / 普通机居中 |
| 旋转 | 1.0 只竖屏，盖子永远是上半屏；倒置竖屏不支持（项目已禁） |
| 进后台 / 回前台 | `interaction` 保持开启；回前台（`scenePhase .active`）清空 `hingeSamples`、更新 `lastAngle`，**不**因为离开期间手机动过就接管；若回来时在外屏 ⇒ §2 外屏规则 |
| 铰链正在动时按钮 / 读屏 / 手指 | 它们收回页（现有 1117 / 1227 行），铰链更新直到停下 300 ms 后都忽略 |
| 更新稀疏（系统策略） | 空闲判定 `idle` = max(300 ms, 2 × 观测到的更新间隔)，否则慢慢合的途中会被当成「停下」而吸附 |
| 第一次更新就是 partiallyOpen 110°（关卡开始时手机半开） | 现有 542 行：直接套上物理角、相机不动、不算撤销步 |

**模拟器（Device Hub → iPhone Duo，iOS 27.1；铰链控件 = 角度 + 三个状态）**，每条对应一个手动用例，前缀 S：
S1 开机（合着）启动：App 在外屏、普通布局、设置项先不出现（未收到 hinge） · S2 拨到 fullyOpen：回内屏，`crease=` 探针 ≈ 475.5，顶栏在下半屏，设置项出现 · S3 3-1 从 180° 慢慢拨到 120°：8° 后接管，影子跟着走，页不翻（相对角 0），每 15° 一下 tick · S4 停在 110°：300 ms 后影子微移到窗口中点、一句 settle 公告，纸不动 · S5 拨到 30°：「啪」、压印 / 粘 / 洇生效；再拨 closed：到外屏；再 fullyOpen：「打开 · 路已接通」 · S6 9-1 一步从 180° 拨到 closed：松石只滚一次、「啪」一次、一步撤销 · S7 手机 110° 时用手指拖页：页相对盖子翻；拖动中拨铰链不接管 · S8 十二章：face 2 半折时拨铰链 ⇒ 提示一次；第三页摊平时拨 ⇒ 自动换回书并折 · S9 铰链折后撤销：虚拟角回去、物理角不动，再拨 ≥ 8° 追回 · S10 设置关「铰链折页」：拨动无效，折痕仍钉 · S11 后台时拨 60°，回前台不接管 · S12 VoiceOver / 减少动态效果各跑一遍 S3–S5。
**自动化**：UI 测试拨不动模拟器铰链 ⇒ 新增 `FakeHinge: HingeProvider`，启动参数 `-hinge fake -hingeSequence "180,150@300,110@600,30@1200"`（角度@毫秒），`FoldDriver` 加 `hinge(to:)`；S3–S9 都能变成 XCUITest。`UIHingeProvider` 只做 Device Hub 手测。
**只能真机**：`shut`、`flatDead`、`takeover`、`idle`、`jitter`、fullyOpen 实际角、是否交到外屏、合上时的触觉是否和铰链阻尼打架、45 pt 格子在盖子上的可点性、§2 的「铰链合上的书画在下半屏」。**真机到了第一天只做标定，不改规则**。

## 7. 范围与建造清单

**1.0**：翻盖握法（竖屏、横铰链）· §1 映射 · §2 钉折痕 + 平视相机 + 相对角 + 盖子无控件 · §3 发现提示 + 现有设置 · §4 十二章规则 · `FakeHinge` 与 S3–S9 自动化 · 真机标定一周（§6 表）。
**以后**：书脊握法（横屏 + 竖折痕 + 全部页面横屏）· 铰链版幽灵手（plan §12.2 四处）· `TiltHinge` · 姿态滞回（若真机需要）· 外屏继续玩。

**建造清单**（按文件）：
1. `Hinge.swift`：按 `status` 映射（fullyOpen ⇒ f 0、closed ⇒ f 180、unknown ⇒ 不可用）；`flatDead`；`lastStatus` 暴露；`FakeHinge`。
