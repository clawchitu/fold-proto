# 《折信》设计评审 · 第一轮（2026-10-16）

评审对象：Claude Design 第一稿 `tmp/fold/design/final-*.jpg`（overview、1-4 墨、3-4 乘影 130°、4-8 两人、书封、设置）+ `notes.md`。
评审人：Fable（主设计）。依据：`plan.md` §3 平台、§9 无障碍、§11「一张纸，三种状态」。
对照物：网页原型的关卡数据 `levels.js` 与规则 `logic.js`（设计稿画的必须是规则允许的）。

**总判断：方向对了，画面还在说谎。** 三帧并排确实是同一本书，纸的「白 → 墨 → 光 → 印」递进成立，封面有记忆点。但棋盘层面有三处硬伤——朱线画出了规则不允许的路、竖屏用了竖折痕导致格子只有 ~40pt、底部七个控件占了三分之一屏——这三处不改，再精致也是一张"看起来像游戏"的插画，而不是一个能玩的界面。

---

## 1. 保留（按价值排序）

1. **一本书的一致性成立。** 顶栏、棋盘框、浮雕格、皮影纸人、朱线在三帧里一个都没换，只有纸色（#F7F4EE → #F1E9D8 → #EBE0C7）、透光、墨饱和、背光四个参数在动。这正是 §11 要的"改参数不重画"，而且商店截图天然成序列。保留，并把这四个参数写进渲染层作为唯一的章节变量。
2. **第三章的背光页。** 右页举到灯前、纤维显形、石头变成黑剪影——这是全套里唯一一张"别的游戏没有"的画面，也是「影」机制的"为什么"。保留，并且它就是主图（见 §7）。
3. **终章「成」印跨中缝一分为二。** 合上才盖得全，印泥在两页上各一半——用一个印章把"折痕是河、两岸相触"讲完了，不用一句话。保留；印章出现的时刻必须是合上那一刻（奖励），不能预先摆在那。
4. **三句关卡引言的语气。** 「墨未干时，合上它。」「把纸举到灯前，影子也是路。」「两岸相触。信，到了。」——短、具体、像信。保留这个写法，36 关都照这个长度来。
5. **封面的构图骨架。** 满屏一个「折」，一道斜向山折横穿字面、上下两侧明暗不同，朱线从顶端垂到「开始」打一个结。这是能记住的一张画。保留骨架，修细节（§6）。
6. **设置页「卡片是一张对角折过的纸」+ 开关用「｜/○」双编码。** 已经在按 §9"不只靠颜色"做。保留。

## 2. 修正（按影响排序）

### 2.1 朱线把整条解法画出来了，而且画了一条规则不允许的路（最高优先）

三帧里朱线都从纸人一路连到旗子，并且在 **180° 打开状态下直接跨过中缝**。`logic.js` 的 `openNeighbours` 明确：打开时两页之间不相通（只有立起的纸片例外）。也就是说这条线展示的路径在游戏里走不了——它在教玩家一个错误的规则："路是连着的，走过去就行"，而这个游戏的全部要点是"只有合上两页才相遇"。

同时它剧透：第一眼就把答案画在棋盘上，玩家没有东西可以发现。

**改法：朱线只画"已经走过的路"，不画"要走的路"。**
- 线从起点出发，跟在纸人身后，像缝线穿过纸；路由格子（浮雕）表达，线只记录进度。
- 合上时两页相触，线在中缝处"穿"到对页——这才是双重身份该有的样子：进度 = 这封信被折了多少次、送了多远。
- 到达终点时线打一个结（与封面「开始」上的结呼应）。
- 这样"路 + 进度"是巧的，不是乱的；现在的画法是乱的。

### 2.2 竖屏用了竖折痕：格子 ~40pt，低于 44pt；拇指也够不到右页

按 366px 稿换算到 393pt 宽的 iPhone，8 列铺满 322pt，一格 ≈ 40pt，`notes.md` 自己也承认了。但根因不是"再放大一点"，而是朝向：`plan.md` §3 写明「**竖屏时折痕水平（上页合到下页），横屏时折痕垂直**」。网格是对称的，这是零成本的决定。

**改法：手机竖屏，折痕横向，上页合到下页。**
- 4 列横铺 393pt → 一格 ≈ 80pt，是现在的两倍；5 行 × 2 页 = 400pt 高，棋盘仍留得下引言和一行状态。
- 拖页变成拇指从屏幕上缘往下拉，单手、顺手，和"折一封信"的动作一致（信纸本来就是横着折的，Letterfold 的"fold"就是这个）。
- 第三章 130° 时上页向后仰、影子落在下页——像打开一张立起的贺卡，俯视可读性比竖立的书页更好。
- Duo 和 iPad 横屏保留竖折痕，就是现在的画。
- 设计稿下一轮要出一张竖屏横折痕的 1-1「桥」，这是 M1 的真实界面。

### 2.3 底部控件太多：滑块 + 打开/立起/合上 + 折一点/展开一点/撤销

七个控件、两行按钮、一条滑块，占了 1/3 屏，而棋盘只占 1/3。ADA 级别的游戏首屏不会有一排写着动作名的按钮——Monument Valley 的屏幕上除了世界什么都没有。完整的交互提案见 §4。

### 2.4 画了不存在的机制和道具

稿里出现了印章立方体、折痕裂缝、压力格、镇纸、第二块石头。这些是 Shuai 提的"候选"（`plan.md` §10 末尾），一个都没入选 §2 的 8 个机制。美术稿不能替设计做机制决定——每多一个形状，新玩家就多一个"这是什么"。另外关卡名也对不上：`levels.js` 里 1-2 是「对页」、1-4 是「钥匙」、1-5 是「墨」；稿上写"1-4 · 对页"却画了墨印。

**改法：每一帧画一个真实存在的关卡，只画它的元素。** 第一帧改为 1-5「墨」（`-xix.-..` 那关：两块石头夹一滴墨，印到对页的缺口）；第二帧严格按 `ride` 关（一块石头、两格缺口、一格影子）；终章画「两人」时只有两个纸人、路、旗。镇纸/压力格等若将来入选，再单独出稿。

### 2.5 "哪格能走"读不出来：白纸上的白色浮雕

第一章的路格靠一条极淡的斜向高光和纸面区分，在 40pt 下已经费劲，在 OLED 的户外亮度下会消失。影子章里"影子格"是一团无定形的灰，横跨 1.5 格，玩家无法判断它占哪个格——而规则里影子是精确的一格。

**改法：**
- 路格要有可触的厚度：底边 1pt 投影 + 比纸深一档的面色（不是只有高光）；高对比模式按 §9 加边框。
- 影子必须是格子形状，边缘软但轮廓是方的；影子滑动是整格滑动（原型已如此）。
- 右页在 130° 时底部那排半透明的路格几乎看不见；背光页上的路要用"透光更亮"而非"更淡的线"表示——纸薄的地方光更强，这在物理上也说得通。

### 2.6 装饰性折痕与引导线

第一章页面上两道横向的"山折/谷折"在机制里没有意义，却和真正会动的中缝用同一种线；玩家会问"这两条也能折吗"。终章从印章到两个纸人的两条白色斜线像辅助线，意义不明。**都删掉。** 这个游戏里，线只有两种：中缝（会动的折痕）和朱线（走过的路）。第四章"折痕发白"可以保留，但只发白中缝。

### 2.7 顶栏冗余

左上「折 折信」logo + 右上两个 28pt 的小图标，再加标题行"1-4 · 对页"。玩家进了关卡不需要被提醒游戏叫什么。**改法：顶栏只留一个「书」（返回章节）图标和一个「?」（提示，第一次卡住时才出现），44pt 热区；关卡名只在进关时淡入 1.5 秒后退到 40% 灰。**

| 朱线双重身份（路 + 进度） | **想法巧，执行错。** 作为"走过的线"它同时是进度条和故事线（信走了多远）；作为"要走的路"它是剧透和谎言。按 2.1 改。滑块上的那条朱线和棋盘上的朱线是两个东西用同一种颜色，去掉滑块后歧义自然消失。 |

## 4. 交互提案：手直接折页，按钮只在无障碍模式

目标：首屏只有纸。所有动作要么是对纸做的，要么在系统级的无障碍通道里。

**主输入：拖页。**
- 竖屏：拇指按住上页任意位置向下拉（不是只有边缘，热区是整页），页随手转；松手吸附到最近的姿态 0° / 90° / 130° / 180°，每个姿态边界一个触觉"咔哒"，合上一个沉的"啪"（§3 已定）。
- 第三章「影」：91°–154° 不吸附，松手停在哪就是哪；130° 有一个软的阻尼感（Core Haptics continuous 的轻微"陷"），这就是"旋钮"的手感。
- 反向：从合上状态拉回去，同一手势。
- 第二手势：双指各按一页向中间捏，合上。

**角度反馈：不要滑块，不要读数。** 页本身转起来就是反馈。只在拖动时，中缝旁浮现一个 11pt 的角度（"130°"），松手 0.6 s 后淡出。章节三的角度窗口用纸的透光度表达——越接近灯，页越亮。

**走路：点格。** 和原型一样，点可达的格子纸人走过去；不可达的格子轻抖一下（原型的 `nope`）。

**撤销：** 棋盘上两指左滑 = 撤销一步（iOS 系统惯例之一），同时在「书」菜单里有「撤销 / 重来」。不占首屏。

**Duo：** 铰链是唯一输入，屏幕上不响应拖页（避免两个输入打架）；但按钮模式（下）在 Duo 上永远可开。

**无障碍模式下的按钮（§9 原则 1 不变）：** 出现条件三选一——设置里打开「按钮控制」、系统正在运行 VoiceOver / 切换控制 / 语音控制（`UIAccessibility.isVoiceOverRunning` 等）、或 AssistiveTouch 开启。出现时是一行 5 个 44pt 的按钮：**折一点 · 展开一点 · 合上 · 打开 · 撤销**（去掉「立起」——它等于按两次折一点，少一个按钮少一次扫描）。它们同时也是棋盘的 `accessibilityCustomActions`，所以读屏玩家不开按钮也能做。方向走一步的四个按钮折叠进「走」子菜单，或者用转子。

**为什么这样够：** 明眼玩家零 UI；运动障碍玩家有完整的、无精度要求的离散路径（15° 步进 + 四个姿态），并且「乘影」按步进可玩是 §9 已经验证过的；读屏玩家走自定义动作和转子，不依赖任何可见按钮。三条路径到同一个规则引擎，没有降级版。

## 5. 无障碍专项（对照 §9，冲 Inclusivity）

**对比度（算过的）**
- 朱线 #C0473A 在新纸 #F7F4EE 上 ≈ 4.6:1，在旧纸 #EBE0C7 上 ≈ 3.8:1。作为图形元素过 3:1 线，作为 2px 细线仍偏险——**线宽 ≥ 3pt**，旧纸章节朱线用 #B23A2E 加深一档。
- 墨色纸人 / 石头在三种纸上都 ≥ 12:1，没问题。
- **问题在中间灰**：第一章的"透到对页的淡墨"、第三章的"影子"、路格的浮雕，都是白底上 1.2–2:1 的灰。影子是可走的路，必须 ≥ 3:1；透到对页的淡墨是提示而非规则，可以淡，但高对比模式下要变成虚线框。
- 背光页（第三章右页）暖黄 + 黑剪影对比够；但该页上的路格几乎隐形（2.5），背光状态下路格 = 更亮的透光区，并加 1pt 描边。
- 「降低透明度」开启时，§11 已定：背光退化为实色剪影 + 描边，三帧都要出这一版的预览给高对比模式用。

**不靠颜色**
- 石头（不规则剪影）、墨（笔触方块 + 字）、纸人（人形）形状各异，过关。
- 影子目前只是"更淡的黑"，与半透明墨印难分；按 §9 影子用交叉线花纹，墨印保持实心——高对比下的差别要在设计稿里画出来，现在设置页只有四个花纹小样，没有一帧棋盘用上它。**下一轮要出一张第三章的高对比帧。**
- 终点旗是全局唯一一个用红色标识的物件，加"双框"（§9 已定）。

**触控目标**
- 改横折痕后格子 ~80pt；按钮 44pt；顶栏图标热区扩到 44pt；拖页热区是整页而非边缘（手部震颤友好）。
- 「大格子」不该是一个开关——44pt 应该是默认。把这个开关改成「超大格子」（≥ 64pt，棋盘可滚动）给低视力玩家。

**运动障碍**
- §4 的按钮模式覆盖全部动作，没有拖动或长按是唯一入口。
- 吸附 + 四个姿态意味着拖页本身也不要求精度；第三章的连续区间给一个"松手就停"而非"必须停在 130°"的宽容度（原型里影子窗口是 91–154°，够宽）。
- 切换控制扫描顺序：折叠动作 → 走 → 棋盘（§9 已定）。

**读屏 / 声音模式**
- 朱线不能是唯一的进度表达：棋盘 `accessibilityValue` 给「第 3 步，离终点 2 格，书已合上」。
- 纸的三种状态要在读屏里有一句话（「这页纸举到了灯前」），否则盲人玩家听不到章节在推进——这是"同一个谜题的另一种感官"要兑现的地方。
- 拖页过程的角度用 `accessibilityValue` 实时更新（"斜起 130°"），松手时播一次 announcement。
- 设置页缺三项：「按钮控制」、「语音朗读（无读屏时）」、「触觉强度」。「差异化不仅靠颜色」跟随系统，不单列。

## 6. 缺失项

- 竖屏横折痕的手机帧（M1 的真实界面）——现在一张都没有。
- 1-1「桥」的教学帧：幽灵手拖页、合上、纸板盖上缺口，三格连环。这是 5 秒内必须发生的事，设计稿得先画出来。
- 合上（0°）状态下的画面：合上时屏幕上是什么？（Duo 内屏熄灭；手机上是合上的书背 + 一秒的"信送到了"）。三种状态都画了打开，没画合上。
- 章节页 / 信纸墨稿（每章一张，§11 的四张手绘件之一）。
- 高对比模式的棋盘帧（§5）。
- 过关动画：线打结、印章落下。

## 7. 商店主图

**主图 = 3-4「乘影」130°，纸人站在影子上，影子正滑到一半。** 理由：它是三帧里唯一一张在别的游戏里看不到的画；它一张图讲完"折叠不是开关而是旋钮"；它和 Duo 的卖点直接对应。去掉所有 UI 铬层，只留纸、灯、影、人，一行字：「影子也是路 / A shadow is a path」。

第二张用 1-1「桥」做左右（或上下）对照：打开——缺口对面有块纸板；合上——它正好盖上来。第三张封面。后面按白 → 墨 → 光 → 印排。

## 8. 下一轮修改清单（≤10）

1. **朱线只画走过的路**，不画解法；合上时穿缝到对页；到终点打结。（2.1）
2. **手机竖屏改横折痕**，出 1-1「桥」和 1-5「墨」两帧竖屏稿，格子 ≥ 64pt。（2.2）
